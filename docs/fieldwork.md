# 照着拍 · 现场拍摄工具

本分支 `feature/onsite-shooting-tools` 将现场拍摄工具同步到 REDcowork 纯前端项目。入口仍为 `/`，顶部 Tab 在杂志版和笔记版间切换，当前流程保留。

## 六项功能在哪里

| 功能 | 入口 | 实际行为 |
| --- | --- | --- |
| 我喜欢参考里的什么 | 这张怎么拍 → 现场拍摄工具 | 选择构图、光影、动作、氛围；取消构图会取消实时框对齐，取消动作会解除固定动作约束。至少留一个偏好。 |
| 先试一下光 | 拍法页或相机顶部 | 用同一相机拍三张不同脸部朝向的真实照片，点选放大、重拍、保存；选择后更新口令。用光方向随拍法保存，试拍图片仅保留本轮，可单独下载。 |
| 构图对齐进度 | 相机取景页 | 本地人体检测同时显示目标框、当前框、人物大小、左右位置和上方留白。人物消失、低置信度或检测超时时清除状态；无可靠检测不展示“已对齐”。 |
| 这里拍不了 | 拍法页或相机顶部 | 窗边不可用、缺少阳光、空间不够、背景杂乱、动作不舒服各有替代方案。更换光线需要明确选择现场条件；换动作或处理空间时保留此前选好的替代光线。可以恢复原拍法。 |
| 导演口令 | 相机顶部 | 取景、人物动作、快门三个步骤；大字提示、说具体点、换动作、按需朗读。切换步骤会停止上一句语音，最后一步实际拍照。 |
| 入戏一下 | 首页独立卡片 | 选择场景、参与人数（含拍摄者）、现有道具、表演尺度；安排角色、台词与 15 秒分镜，下载文本剧本、倒计时后真实录像、回放并下载短片。 |

## 使用与能力边界

- 相机与麦克风需要 HTTPS 或 localhost 和浏览器权限。三张试光、构图检测及录像在本机处理；朗读使用设备或浏览器的语音服务，优先选用本地中文语音。
- 试光由用户比较实际画面，保留个人偏好；没有自动美学打分、测量光源方向或修改曝光。手机自动曝光可能使三张明暗差异缩小。
- 构图进度比较二维人物范围，不推断现实距离、相机姿态或精确焦距。遮挡、多人物和检测失败时可继续手动拍照。
- 现场替代拍法来自明确条件与编辑规则；“入戏一下”使用按场景、人数、道具适配的精选脚本，界面明确标注。此版不声称模型现场生成剧本，也不生成虚拟视频。
- 录像为原始相机视频，口令与字幕不烧录到画面。支持 MP4 时优先 MP4，否则 WebM；不支持 MediaRecorder 的浏览器可以下载剧本用系统相机拍。
- 视频只在当前页面保留。未下载时离开会提醒，页面隐藏或组件关闭会停用相机。浏览器下载提示出现不等于系统照片相册已经保存。
- 此仓库不请求 `/api/*`，不包含后端或密钥。AI 分析按钮继续明确显示未接入，用户可以手动选站位。完整前后端版保留在 `xiaoa0660-create/hey` 同名功能分支。

## 验证

单元测试覆盖偏好生效、可逆替代光线、试光与动作组合、低置信度/无人物/多人物、镜像对齐、复拍状态以及脚本角色和道具限制。浏览器测试覆盖两种主题的保存恢复、三张真实 Canvas 帧的拍摄与导出、录像文件回放下载、15 秒自动停止、权限拒绝和离开前保存提醒。

使用 Chromium 和受控 Canvas 摄像头流验证，未在真实 iPhone/Android 设备上验收。真实外部视觉模型效果、现场检测精度及各浏览器语音质量仍取决于设备与部署环境。

共享功能代码在完整版通过 79 项单元测试和 21 项浏览器测试；独立纯前端构建还验证了两种风格与零后端请求。本仓库只保留部署所需的前端代码。

## 构建与发布

```bash
npm ci --cache /tmp/zhaozhepai-npm-cache
npm run build
```

发布目录为 `dist`。将本分支地址交给 REDcowork 拉取代码，在工作区构建，并按其 STATIC_SITE 流程发布。产品入口、原有图片、广告和手册均保留。

这仍是独立功能分支；仅推送此分支不会更新现有 main，也不表示 REDcowork 已重新发布。不要把此静态包覆盖到需要视觉后端的 Netlify 完整版。
